跟 AI 一起用 Git｜不背指令的版本控制

壹這是給誰的

給手上有研究專案的大學教師與研究生。判斷方式很簡單：如果你的資料夾裡出現過 論文v3_最終_真的最終.docx，或是你跟共同作者用附件來回改稿改到不確定哪一份才是最新的，這門課就是為你開的。

你不必先會

  • 任何 Git 指令
  • 終端機、命令列
  • 任何一種程式語言

你要有

  • 一台能上網的電腦
  • 一個 GitHub 帳號
  • 一個你慣用的 AI 助手（本課的示範工具是 Antigravity，換成別的 agent 也走得通）
這門課不教什麼

不教你背指令，也不講 Git 內部原理。stash、rebase、amend、fork 工作流、GitHub Actions 全部跳過——需要它們的時候，你的 agent 會用，你只要看得懂它的計畫。真正要練的是另一件事：當它的指導教授，不是它的橡皮圖章。

貳要花多久

全程約 95 分鐘的實作，分成兩個階段。時間是「順順走完」的估計，第一次做慢一點很正常。

⚠️ 一個人自學的話，請先只走第一階段

第二階段是工作坊用的，需要兩個人——一位當研究生、一位當指導教授，輪流提出修改與把關。整段練的就是「兩個人怎麼在同一份稿子上不打架」，一個人做不出那個情境。

第一階段（P1–P9）本來就是你一個人的研究專案，自己走完全沒問題，而且走完就已經解決最痛的那一半：版本回得去、東西備份在 GitHub、看得懂改了什麼。第二階段等你找到共同作者、指導的學生，或參加正式場次再做。

請不要為了湊人數另外註冊一個 GitHub 帳號自己扮兩個角色。GitHub 服務條款寫明一人最多只能維持一個免費帳號，這不值得為了練習去踩。

參開始之前要先準備

三件事，全部要在開始之前弄好，不要留到走到一半才發現裝不起來。

  1. 裝好並登入你的 AI 助手。完成判準：打得開、登入成功、找得到那個可以打字的輸入框。
  2. GitHub 帳號能登入。
  3. 做一次「小試身手」：讓 AI 建一個小資料夾跟一個檔案，順便回報 git 版本與 GitHub 登入身分。一句話就驗完整條安裝鏈，而且你要自己把檔案打開看——AI 說做完了，不等於真的做完。

完整清單、每一步的截圖與「卡住了怎麼問 AI」的求救句，在教材的〈行前準備〉一節。這裡只列最小要件，不重複寫一份。

肆15 關全景：每一關做什麼、哪裡要你自己看

這張表是整門課的地圖。最右邊那一欄最重要——那是 AI 做完之後，你一定要自己核對的東西。這門課的價值不在指令，在這一欄。

關卡名稱可點，直接跳到教材對應段落。
關卡 分鐘 這一關你會做什麼 你一定要自己看的

伍兩條資料紅線（跟技術無關，跟你的責任有關）

這兩條放在最前面講，因為它們不是技術問題，出事也不是技術能補救的。

一、學生個資與未發表資料，不進公開 repo

成績單、名冊、還在審的稿子，公開版本庫一律不放。研究協作請用私人 repo，公開前仍要逐檔確認。

.gitignore 不是保密工具——它只能協助排除「還沒被追蹤」的檔案，不能取代你自己的資料判斷與權限設定。

二、私人 repo 也不放帳號密碼

密碼、API 金鑰（API key）一旦提交過就進了歷史，事後刪掉目前的檔案不代表舊紀錄消失。敏感資料放在專案資料夾外面。

萬一真的存錯了：先停手，尤其別 push，然後照教材的〈急救箱〉一步一步處理。已經 push 出去的要當成外洩處理，不是刪一刪就沒事。

陸三條誠實限制

先講清楚這門課做不到什麼，你才知道學完之後手上有什麼、沒有什麼。

  1. Word 和 Excel 在 Git 裡看不到逐行差異。它們不是純文字檔，diff 只會說「檔案變了」。Git 對純文字檔（.md、.R、.do、.tex、.csv）才火力全開。Word 一樣可以放進版本庫備份與同步，只是「追蹤修訂」那種體驗要靠 Word 自己。
  2. GitHub 的方案功能會變。分支保護之類的功能在公開／私人 repo 上可用範圍不同，也會隨帳號與組織方案變動。真正的研究資料要先判斷能不能公開，不能為了拿到某個功能就把敏感資料改成公開。開始前請以官方頁面現況為準。
  3. agent 會犯錯，所以概念才要懂。它可能改錯檔案、寫錯說明、在你不想動的分支上動工。你不必背指令，但你得看得懂它的計畫和 diff。

完整版在教材第拾章。

柒我學會了嗎

走完第一階段之後，用這幾句話問自己。答得出來才算真的走過，闖關頁的進度條只是輔助。

  • 我知道 Git 管的是「一個資料夾」，而且講得出我現在在哪個資料夾。
  • 我能讓 AI 把一份修改存成一個版本，而且存之前我看過它改了哪幾行。
  • 我能把專案推上 GitHub，並在網頁上看到它。
  • 我看得懂歷史紀錄，能比較兩個版本差在哪裡。
  • 我知道「只是看看」「restore」「revert」是三種不同的回去，也知道哪一種在已經推出去之後才安全。
  • 我知道哪些檔案不該進版本庫，也知道 .gitignore 不是保密工具。
  • 我知道 agent 說「做完了」不等於做完，我會自己把檔案打開驗。
  • 我知道任何時候都可以喊停，也記得那句救援句怎麼說。

捌學完之後，下一步做什麼

  • 把一個真的研究專案搬進來。先判斷資料能不能公開；不確定就開私人 repo。
  • 把常改的檔案換成純文字。筆記改 .md、論文改 .tex，逐行差異才看得到——這是第陸節第一條限制的解法。
  • 找一位共同作者或你指導的學生，補走第二階段。兩個人一起做過一次 PR，之後真的協作才不會卡。
  • 如果你的期刊要求附上資料與程式，這套流程就是底層：完整的修改歷史、乾淨的檔案清單、說得清楚每一版差在哪。
